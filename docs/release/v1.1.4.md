## 2. 相对 v1.1.2 的核心变化

### 2.1 播放运行时架构重构（T00-T08）

本轮重点不是增加功能，而是对播放控制面做系统化架构重建：

**T00-T02：播放基础链路**
- `device_player.py` 引入结构化 `_play_list_items`（list[dict]），external URL bootstrap 优先按 `playlist_item_id → entity_id → display_name → legacy_name → index fallback` 定位
- `Device` 类新增 `current_entity_id` / `current_playlist_item_id` / `current_display_name` 三个显式 identity 槽位
- `PlaybackFacade.build_player_state_snapshot()` 作为 `/api/v1/player/state` 与 SSE 的唯一权威状态来源

**T03：运行时状态与快照**
- `RuntimeState` 统一管理设备运行时状态，`RuntimeStateDevice` 封装单设备实例
- `get_offset_duration()` 保持纯读，timer 最多延期三次，第四次推进下一首
- 后台启动确认不破坏性重播同曲，当前后台任务不会被 session bump 自取消

**T04：播放仲裁器（Arbiter）**
- `PlayArbiter`（C2B）：统一 play 意图的合法性裁决与冲突解决
- `ExternalUrlArbiter`（C2C）：外部 URL 播放路径的对位与校验
- `DeferredFallback`（C2D）：延迟回退逻辑，确保播放失败时有明确退路
- `AutoNextRetryArbiter`（C3A）：自动切歌重试的仲裁与限流
- `CheckReplayArbiter`（C3B1）：防止同曲复播的守卫

**T05：失败处理与重试归属**
- 播放失败重试的归属逻辑明确化，区分设备侧、来源侧、网络侧失败的不同处理路径
- `retry_same_song_with_sync_stop` 不再残留触发

**T06：播放任务注册表**
- `PlaybackTaskRegistry` 统一管理活跃播放任务的生命周期，消除任务泄漏和孤儿任务

**T07：遗留推断清理**
- 移除 name-based 旧结构的残留推断路径，统一走 entity/playlist_item 身份链

**T08：命令仲裁器**
- `CommandArbiter` 统一播放控制命令（play/next/prev/stop）的路由与冲突裁决
- next/previous 不再调用 `/api/v1/play`，统一进入 `XiaoMusicDevice._play_next/_play_prev`

### 2.2 WebUI 控制意图

- 歌曲 selector key 从 `item.id` 改为 `${effectivePlaylist}:${item.id}:${idx}`，解决重复 id 导致的 React 残留
- `HomePage.tsx` 播放按钮行为、歌单切换、pending selection 生命周期已对齐后端 identity 体系

### 2.3 架构与文档

- `docs/adr/` 新增架构决策记录
- `docs/api/` 新增 API 契约文档
- `docs/spec/` 新增播放规范与 relay 契约
- `docs/architecture/` 更新到当前实现
- `ARCHITECTURE.md` 更新

### 2.4 安全加固

- hardened docker-compose：`read_only: true` rootfs、`no-new-privileges`、`cap_drop: ALL`、`pids_limit: 200`
- 日志脱敏：API 与日志不泄漏 token / Jellyfin API key
- `XIAOMUSIC_ENABLE_EXEC_PLUGIN: "false"` 默认关闭
