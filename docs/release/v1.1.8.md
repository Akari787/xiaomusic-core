# v1.1.8：认证身份一致性与保活诊断

日期：2026-11-22。版本入口：`pyproject.toml`、`xiaomusic/__init__.py`。

## 用户可见变化

扫码与续期沿用同一 UA 和设备标识，降低跨请求身份不一致风险。长期凭据年龄作为普通信息显示，不再在60小时后建议扫码；续期被拒或需要人工认证时仍明确警告，当前播放运行时可用性独立展示。

成功保活每轮清零连续失败计数；连续三次失败进入退化后，首次成功只记录一次恢复。诊断包含实际探测、门禁、结果类别、连续失败数与进程内累计计数。`probe_failure_total` 统计有实际探测且最终失败的保活轮次；`gate_skip_total` 统计无实际探测且存在门禁的失败轮次。计数随进程重启归零。

保留12小时调度、验证后原子CAS、扫码凭据代际校验、拒绝空值/删除标记及禁止隐式密码登录。验证恢复清理旧cooldown/backoff，但普通运行时恢复不解除长期续期挂起门。

可选cookie观测不再记录凭据指纹、长度或异常原文；健康探测错误只保留网络/认证类别。历史观测文档已脱敏并修正过强因果结论。容器默认时区采用Asia/Tokyo。

11月6日扫码的测试候选持续约15天20小时，31次计划触发均有换票及验证后CAS提交；长期凭据未轮换，容器重启计数0，最后提交为11月22日02:20:29 JST。

这是单账号、单周期观察，支持身份一致性方案有效；单次保活失败原因仍未知。75条不健康警告和25条恢复记录受旧计数缺陷影响，不能据其数量直接判断网络故障或凭据失效。
