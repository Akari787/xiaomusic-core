# v1.1.6 发布说明

发布日期：2026-09-19
适用分支：`main`（本次在 `fix/auth-runtime-rebind` 分支完成，待合入）
基线：`v1.1.5`（`f7c1cbd`）

---

## 1. 发布目标

修复"重启后必须重新扫码、且经常扫了也播不了"的认证问题；并补齐容器 DNS 的自愈能力（部署层）。

本版**不改动**播放协调器、设备播放器、来源解析与 WebUI 交互；改动集中在认证状态机与运行时绑定。

---

## 2. 主要变化

### 2.1 认证：重启免扫码

三处改动，缺一不可：

1. **`set_token` 重建 `micoapi` 会话元组。**
   持久化的 `auth.json` 把 micoapi 会话拆成平铺的 `ssecurity` + `serviceToken`，而 miservice 的
   `MiAccount.mi_request(sid)` 只有在 `token` 中存在该 sid 时才直接使用，否则退回
   `login(sid)`——本部署没有账号口令（`.env` 无密码），那条路必然失败。
   `set_token` 现在把二者拼回 `token["micoapi"] = (ssecurity, serviceToken)`；
   缺 serviceToken 时不伪造。

2. **`_try_login` 快速路径：有会话就直接重绑运行时。**
   当 `mina_service` 未绑定但 auth 数据已有会话 token 时（典型场景＝进程重启），先用新增的
   `_build_verified_runtime_candidate()` 构造候选 `MiAccount` / `MiNAService` / `MiIOService`
   并 `device_list()` 校验；**校验通过后才一次性提交**到 `self`。全程不发起 `login`。
   校验失败时不写回任何运行时字段，因此不会覆盖并发建立起来的运行时。

3. **登录风暴根因修正。**
   `_maybe_scheduled_refresh` 的 TTL 基准与最小间隔基准，从 `saveTime`（只在新 token 与旧 token
   不同时才推进，token 稳定后 TTL 永远显得"已过期"）改为 `_last_login_ts` / `_last_ok_ts`。
   实测此前为 **12 次/小时**的强制登录。

### 2.2 DNS 自愈（部署层）

宿主机新增看门人 `docker-dns-watchdog`（systemd timer，每 2 分钟）：容器内解析失败**且**宿主能解析
→ 重启容器重建网络 sandbox；宿主也解析不了则不动手；每容器每小时重启上限 3 次，到顶置位失败
等待人工介入。**该脚本属部署层，不进入本仓库。**

### 2.3 时区

仓库默认保持 `Asia/Shanghai`。`TZ` 属部署覆盖：本机在日本，由部署 compose 覆盖为 `Asia/Tokyo`。

## 3. 兼容性边界

- 不删除、不改名任何公开 API；v1 请求/响应形状不变。
- `set_token` 新增的是 `account.token` 内的键，不改变持久化文件格式。
- `_last_fast_rebind_state` 为新增只读审计字段，已在 `auth_recovery_debug_state` 暴露。

---

## 4. 发布门禁

- **单元测试**：`tests/test_auth_runtime_stability.py` **14 passed**（新增 5 条）。
  关键几条已逐一验证"对修复前代码必失败"，确认为真门禁而非装饰。
- **独立审查**：由影子澪两轮独立审查。第一轮判"需修正后再审"（清理不完整 / 并发丢更新 /
  审计缺口 / 零测试覆盖），逐条修正后第二轮判**可交付**（余项为 P2 级跟进）。
- **实机（测试服务器 192.168.7.178 / OH2P）**：
  - 容器重建后日志出现 `认证成功（已持有会话，直接重绑运行时，未发起登录）`，
    **未扫码即恢复**；`auth_mode=healthy`、`runtime_auth_ready=true`、`recovery_failure_count=0`。
  - 随后 15 分钟内 `认证失败 / 87001 / 70016 / 认证不可用` 计数均为 **0**。
  - `/api/v1/play` → `code=0, status=playing, source_plugin=jellyfin, transport=mina`；
    `player/state` 观察到 `transport_state=playing` 且 `position_ms` 递增。
  - 安全协议：播放前音量置 0 并回读（物理回读为最低值 4）；结束后 `stop`，原始设备 `status=2`。
- **未覆盖**：全量 Python 套件中 `tests/unit/test_auth_self_heal.py` 与现行实现脱节
  （monkeypatch 了 `auth.py` 中不存在的方法），属已知基线，不能作回归证据；本版未修该套件。

---

## 5. 已知跟进项（P2，不阻塞）

1. 补一条**并发/顺序**层面的回归测试，覆盖"失败路径不得写回 self"在多协程下的表现
   （现有 clobber 用例已用钩子模拟并发，可再加强）。
2. TTL 锚点目前只在内存，且 `max(saveTime, _last_login_ts)` 会**高估**剩余寿命；
   建议新增持久化字段 `last_verified_at`（在 `device_list` 校验成功时写入），跨重启存活。
3. 把 `87001` / `70016` 归类为"需要人工扫码"，停止无限重试并在状态接口显式暴露。
4. `_last_login_ts` 恒为 0 且 `_last_ok_ts` 被探针刷新时，计划内刷新可能被长期抑制（低概率）。

## 6. 回滚原则

- 改动仅落在独立分支 `fix/auth-runtime-rebind`。
- 测试服务器保留原镜像不可覆盖标签 `xiaomusic-core:v1.1.5-final`（`2a1cb8e0a563`）与
  改动前源码 `xiaomusic/auth.py.bak-pre-authfix`。
- 任一门禁失败即回滚到上述镜像与源码，不推送 `main`。
