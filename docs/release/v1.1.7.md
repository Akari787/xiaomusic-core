## 2. 主要变化

### 2.1 私有 SSO 与持久认证边界

- 官方 OAuth 不替代 `micoapi`。私有 SSO 的最小持久能力是 `userId + passToken + deviceId`。
- 没有账号密码时不执行 full login；候选 `MiAccount` 使用隔离的 `MemoryTokenStore`，避免污染现有运行时。
- 对外审计路径固定为 `used_path=miaccount_persistent_auth_exchange`，实现不调用 `MiAccount.login`。
- startup 从持久化 `saveTime` 同步 `login_at`；`env override` 支持 unknown，NaN/Inf 输入安全归零。

### 2.2 TTL、错误分类与恢复门

- TTL 配置实际生效。unknown TTL 以 12h scheduled 作为辅助轮转，reactive 401 是主要恢复路径。
- 网络错误和未知错误不再误导为扫码；`70016 + captchaUrl=null` 分类为 `credential_session_rejected`，`87001` 或 truthy captcha 分类为 `interactive_captcha_challenge`。
- 两类错误均为 `long_term_expired=false`；scheduled 路径保留 healthy 并 suspend，后续零刺激重试。
- reactive/manual 永久 gate 与 verified 恢复路径统一；诊断、失败计数与 cooldown 收敛。

### 2.3 QR 后 verified rebind

- QR 保存后使用现有 short session 执行 verified atomic rebind。
- verified-only reinit 不执行 exchange/login；失败时保留旧 runtime，避免半成品候选覆盖可用会话。
- 自动测试覆盖磁盘新 auth → candidate → verify → swap 及零 exchange/login；本版不把它表述为再次完成第二遍真实扫码端到端验收。

### 2.4 HTTP Basic 与敏感插件边界

- `/api/js-plugins*`、`/api/openapi*`、`/api/plugin-source*` 使用独立 `strict_verification`，不受 legacy no-auth override 影响。
- 新 `Config` 默认 `disable_httpauth=false`、`httpauth_username=admin`；显式旧用户名仍有效。`HTTP_AUTH_HASH` 优先于 `HTTP_AUTH_PASSWORD`，两者缺失时 CLI fail-closed。
- 既有持久化 setting 可能保留 legacy 开关，升级者需显式确认关闭；本次测试服已改为 `false`。
- 上传拒绝空名、绝对路径、POSIX/Windows 分隔符穿越、NUL 和非单一 `.js` basename；合法上传行为保持不变。`AuthStaticFiles` 已移除 `assert` 鉴权调用。
- Compose 同时显式传递 hash/password，由 CLI 执行二选一契约；`.env.example` 的 password/hash 两类凭据示例均用单引号包裹，避免 Compose 对 `$` 做变量插值。

### 2.5 Node 运行时依赖与 ARMv7

- 根 lockfile 版本：axios `1.20.0`、follow-redirects `1.16.0`、form-data `4.0.6`、qs `6.16.0`、undici `7.29.1`。
- follow-redirects/Axios 测试精确验证默认敏感头策略与 `sensitiveHeaders` 调用方责任；另覆盖 form-data CRLF、qs GHSA-4mjr 与 axios prototype gadget。
- ARMv7 builder/runner 使用 Alpine；builder 增加 `cargo` 与 `linux-headers`，仅用于原生扩展编译。
