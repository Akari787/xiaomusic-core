v1.1.7 发布说明 ​

发布日期：2026-09-22 分支：fix/auth-refresh-state-machine 发布源：tag v1.1.7 指向的提交；已验证运行时代码提交 58a4361d（其后仅发布文档变更）。 源 artifact SHA256（基于 58a4361d）：27789efda2e8a34eba28a929600ef3f0c14dd1cc77793cacd754679c1fd8fdce

1. 发布目标 ​

收敛认证刷新状态机、持久认证交换与 QR 后恢复，恢复内网部署的默认可用性，并在不破坏设备媒体数据面的前提下收紧管理与插件边界。

本版不改变公开 API 形状、播放协调器与来源实现。正式服务器 192.168.7.5 全程未触碰。

2. 主要变化 ​

2.1 认证状态机与持久会话 ​

  • 最小持久能力是 userId + passToken + deviceId。无账号密码时不执行 full login；候选 MiAccount 使用隔离 MemoryTokenStore，不污染现有运行时。
  • 对外审计路径固定为 used_path=miaccount_persistent_auth_exchange。
  • TTL 配置参与调度；unknown TTL 以 12h scheduled 辅助轮转，reactive 401 为主恢复路径。
  • 70016 + captchaUrl=null → credential_session_rejected；87001 或 truthy captcha → interactive_captcha_challenge。scheduled 刷新命中这两类拒绝时保留现有 healthy runtime 并挂起后续自动刷新，等待 verified recovery。
  • DNS / connector / 网络 errno 沿异常链分类。健康探测遇到网络瞬断只进入 cooldown，cooldown 后优先重探现有 runtime；不触发持久认证交换、manual gate 或 destructive login，auth_call 也不会因此调度后台恢复。
  • is_network_error 只把 HTTP 500–599 视为网络状态，不把业务码（如 .code=70016）误判为网络错误。
  • QR 保存后使用现有 short session 做 verified atomic rebind；失败保留旧 runtime。

2.2 内网部署默认无鉴权 ​

  • 普通内网部署默认 XIAOMUSIC_DISABLE_HTTPAUTH=true，无需 HTTP_AUTH_HASH 或 HTTP_AUTH_PASSWORD 即可启动；Config 与 CLI 对开关值统一做 strip().lower() 归一。
  • 只有显式 XIAOMUSIC_DISABLE_HTTPAUTH=false 时 CLI 才要求凭据并 fail-closed。
  • docker-compose.hardened.yml 是主动选择的鉴权模板，不是默认。
  • 插件、OpenAPI、插件源路由使用可被 no-auth 模式覆盖的普通 verification：默认内网模式匿名可用，显式启用 Basic 后仍拒绝无效凭据。

2.3 设备媒体数据面与管理面分离 ​

  • 公开读面只包含 /music/*、/picture/*、/static/silence.mp3、/static/search.mp3 与服务端签发的 proxy token；管理写接口仍跟随部署鉴权模式。
  • 媒体路径使用 Path.resolve() + relative_to()，阻断 .. 回溯、绝对路径、兄弟前缀（music vs music_evil）与符号链接越界。
  • 匿名 /proxy 只接受服务端签发的 t.<token>；legacy base64 URL 仅在显式启用 Basic 时要求有效凭据。
  • 插件上传拒绝空名、裸 .js、NUL、POSIX/Windows 绝对路径、正反斜杠子目录与目录穿越；文件名预检只检查 multipart part header，不再扫描文件内容（避免正文出现 filename="a/b" 时误拒合法上传）。
  • AuthStaticFiles 不再用 assert 执行认证。

2.4 依赖与构建 ​

  • 根 Node lockfile：axios 1.20.0、follow-redirects 1.16.0、form-data 4.0.6、qs 6.16.0、undici 7.29.1；官方 registry npm audit --omit=dev 为 0。
  • Node 安全门禁覆盖 redirect 敏感头、form-data CRLF、qs GHSA-4mjr、axios prototype gadget。
  • ARMv7 使用 Alpine builder/runner，并补齐 cargo 与 linux-headers。
  • 正式 AMD64 / ARM64 / ARMv7 镜像由 v1.1.7 tag CI 构建、测试并发布，本机不再手工构建多架构镜像。

5. 发布流程 ​

  1. 候选分支已 push 到 Akari787/xiaomusic-core；无斜杠验证分支的 AMD64 CI 已完成构建、Python import 与 Node 安全测试。
  2. fast-forward 合入 main 并 push。

  4. tag CI 构建并测试 amd64、arm64、armv7，随后发布 Docker Hub 多架构镜像（v1.1.7 / latest / stable）与 GitHub Release（release notes 取自 CHANGELOG 对应章节）。

6. 已知限制与未做事项 ​

  • 仓库既有 106 failed 基线问题不在本版范围。
  • 启动时 setting.json 与 env 的 disable_httpauth 优先级边界未重构：曾以鉴权模式运行过且残留 disable_httpauth=false 的部署，去掉 env 开关后仍可能回到鉴权模式，需要显式确认配置来源。
  • 公开媒体面未加扩展名白名单；已认证 + no-auth 模式下 legacy /proxy 未接入 OutboundPolicy（纵深防御项，均不阻断本版）。
  • 本版未做长时间多日稳定性观察，长时行为以测试服务器持续观察为准。
