v1.1.5 发布说明 ​

发布日期：2026-07-30 适用分支：main 基线：v1.1.4（fa2fd0a）

1. 发布目标 ​

v1.1.5 是 API 边界与状态通道治理补丁，不改动播放协调器、设备播放器和运行时仲裁实现。

本版解决两类长期偏差：

  1. WebUI 管理与诊断能力占用 Runtime Public API 命名空间，公开 schema 与 25 项正式白名单不一致。
  2. WebUI 会读取播放命令响应中的即时状态快照，与 SSE / player/state 权威状态通道形成并行来源。

2. 主要变化 ​

2.1 API 分层 ​

  • Runtime Public API：/api/v1/*，公开 OpenAPI 精确保留 25 项正式接口。
  • Admin API：新增 /api/admin/v1/sources/* 与 /api/admin/v1/auth/status。
  • Internal Diagnostics：新增 /api/internal/diagnostics/*，不进入公开 schema。
  • 原 /api/v1/sources/*、/api/v1/auth/status、/api/v1/debug/* 保留兼容，隐藏并标记弃用。
  • 新旧路径共享业务实现和唯一 PlaybackFacade。

2.2 请求边界 ​

  • PlayRequest、ResolveRequest 拒绝空白 query。
  • source_hint 限制为正式枚举。
  • options 使用结构化模型并严格验证布尔字段。
  • 未声明的顶层字段和 options 字段被拒绝。
  • v1 422 返回统一 envelope，并包含 E_INVALID_REQUEST 与 stage=request。

2.3 WebUI 状态来源 ​

  • Sources 页面切换到 Admin API。
  • 首页不再读取 POST /api/v1/play 的 data.state。
  • 播放器展示只由 SSE 或 /api/v1/player/state polling 更新。
  • 过期或伪造的命令响应状态不会覆盖权威页面状态。

3. 兼容性边界 ​

  • 本版不删除旧 API 路径。
  • 本版不删除 /api/v1/play 后端响应中的 data.state，仅停止 WebUI 消费。
  • 本版不删除 player/state 的旧兼容字段。
  • 后续移除需另行完成调用方调查并按破坏性变更处理。

4. 发布门禁 ​

发布前必须完成：

  • Python API 专项与相关回归通过。
  • WebUI Vitest 与 TypeScript 检查通过。
  • 测试服务器完成完整源码包构建，不允许散件覆盖。
  • 容器版本、健康、公开 OpenAPI、Admin API、WebUI 静态资源通过。
  • 实机前设置测试设备音量为 0，并回读确认。
  • 播放与状态流验收结束后执行 stop，再 probe 确认 status=2。
  • 上述门禁全部通过后方可推送、打 v1.1.5 标签并创建 Release。
